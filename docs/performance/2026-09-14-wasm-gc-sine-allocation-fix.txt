Wasm-GC sine allocation fix — 2026-09-14

Scope and state
Independent branch: fix/wasm-gc-sine-allocation, based on
0979c8e8e3cfd0cf40fd4a85aae6cebb3194ba51 at measurement time.
The original dirty main checkout and installed core math sources were not edited.

Only the Wasm-GC oscillator's sine calculation changes. The private bounded
kernel retains core's coefficients, reduction cutoffs, cancellation corrections
and floating-point evaluation order, replacing its two-element scratch array
with scalar locals. It supports the oscillator's phase[0,1], including rounded
wrap-to-one and existing scalar-overflow NaN behavior. It is not a general sine
API. Other targets continue using core math.sin; public .mbti files are unchanged.
Graph lifecycle, control semantics, browser interfaces and their documentation
are intentionally unchanged. Source provenance/license remain with the kernel.

Numerical verification
- Three permanent regression tests check65537 evenly spaced phases, signed zero,
  minimum subnormal, neighborhoods of quadrant/octant and high-word reduction
  boundaries, cancellation, wrap-to-one, overflow and reset. Finite comparisons
  use exact Double bit patterns against core math.sin, not an error tolerance.
- The original and fixed browser WASM render4,718,592 samples across nine graph
  configurations with zero mismatches (Object.is, including signed zero).
  Cases include zero, negative and tiny frequencies, quadrant steps,16-graph
  mixing and62 gains. This is measured equivalence, not exhaustive enumeration
  of every Double input; the helper is private and range-bounded.

Allocation verification
Generated release WAT: the sine entry point calls only two scalar kernels.
All three contain only scalar numeric/control operations: no heap/reference
operations and no calls outside this three-function set. The former scratch
allocation is absent from the executed sine call graph, rather than merely
uncollected during a short run.
